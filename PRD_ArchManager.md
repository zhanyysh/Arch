**PRODUCT REQUIREMENTS DOCUMENT**

Платформа управления архитектурными проектами

*Версия 1.0 · Апрель 2025*

**1. Обзор продукта**

Данный документ описывает требования к веб-платформе для
централизованного управления архитектурными проектами. Платформа
обеспечивает единую среду, в которой строительные и архитектурные
компании могут отслеживать ход своих проектов, координировать команды и
контролировать этапы работ в режиме реального времени.

  **Название продукта**   ArchManager --- Платформа управления
                          архитектурными проектами

  **Версия документа**    1.0

  **Дата**                Апрель 2025

  **Статус**              В разработке

  **Контактный номер**    +996 777 77 77 77
  ----------------------- -----------------------------------------------

**2. Цели и задачи**

**2.1 Бизнес-цели**

-   Предоставить единую платформу для управления несколькими
    архитектурными проектами разных компаний

-   Повысить прозрачность и контроль на каждом этапе строительного
    проекта

-   Упростить взаимодействие между менеджерами, прорабами и рабочими

-   Сократить время на отчётность и согласование задач

**2.2 Цели продукта**

-   Создать удобный интерфейс для трёх типов пользователей с разными
    уровнями доступа

-   Обеспечить визуальное отслеживание этапов разработки каждого проекта

-   Реализовать систему управляемого доступа --- аккаунты создаёт только
    администратор

-   Разработать привлекательную Landing Page для привлечения новых
    компаний

**3. Пользователи и роли**

Платформа поддерживает четыре роли. Доступ к системе предоставляется
исключительно через администратора.

**4.7 Фотоотчёт по задачам**

Система фотоотчётности позволяет визуально подтверждать выполнение
задач. Используется гибридный подход: фото \'До\' является
необязательным (прикрепляется при создании задачи прорабом), фото
\'После\' --- обязательным условием завершения задачи работником.

**Концепция: жизненный цикл задачи с фотоотчётом**

+---------------------+---+---------------------+---+--------------------+
| **1. СОЗДАНИЕ       | * | **2. ВЫПОЛНЕНИЕ**   | * | **3. ПРОВЕРКА**    |
| ЗАДАЧИ**            | * |                     | * |                    |
|                     | - | *Работник*          | - | *Прораб /          |
| *Прораб / Менеджер* | \ |                     | \ | Менеджер*          |
|                     | > | **Фото После        | > |                    |
| **Фото До           | * | (ОБЯЗАТЕЛЬНО)**     | * | **Сравнение До и   |
| (необязательно)**   | * |                     | * | После**            |
|                     |   | Без фото нельзя     |   |                    |
| Чертёж, эталон или  |   | завершить задачу    |   | Одобрить или       |
| текущее состояние   |   |                     |   | вернуть на         |
| объекта             |   |                     |   | доработку          |
+---------------------+---+---------------------+---+--------------------+

**Пользовательские сценарии: фотоотчёт**

-   Как прораб, при создании задачи я хочу прикрепить фото эталона,
    чтобы работник понял что именно нужно сделать

-   Как работник, я хочу видеть фото \'До\' на экране задачи, чтобы
    понять ожидаемый результат до начала работы

-   Как работник, при завершении задачи я обязан загрузить фото
    результата --- система не позволит завершить без него

-   Как прораб, я хочу видеть фото \'До\' и \'После\' рядом, чтобы
    быстро оценить качество выполнения

-   Как прораб, если результат не устраивает, я хочу вернуть задачу с
    комментарием что нужно переделать

-   Как менеджер, я хочу просмотреть все фото по этапу в одной галерее
    для оценки прогресса на объекте

**5. Нефункциональные требования**

**5.1 Производительность**

-   Время загрузки страниц --- не более 2 секунд при стандартном
    соединении

-   Поддержка до 500 одновременных пользователей на начальном этапе

-   Доступность системы (Uptime) --- не менее 99.5%

**5.2 Безопасность**

-   HTTPS для всех страниц и запросов

-   JWT-токены с ограниченным сроком действия

-   Разграничение данных между компаниями --- компания A не может видеть
    данные компании B

-   Логирование всех действий администратора

**5.3 Удобство использования**

-   Интерфейс на русском языке (с возможностью добавления кыргызского)

-   Адаптивный дизайн для мобильных устройств и планшетов

-   Не более 3 кликов до любой ключевой функции

**5.4 Масштабируемость**

-   Архитектура должна поддерживать добавление новых типов компаний и
    проектов

-   Возможность подключения внешних интеграций в будущем (мессенджеры,
    бухгалтерия)

**9. Приоритеты разработки (MoSCoW)**

**Must Have --- Обязательно**

-   Landing Page с контактным номером для получения аккаунта

-   Система авторизации (вход, сессии, роли)

-   Фото \'До\' при создании задачи (необязательное, прикрепляет прораб)

-   Фото \'После\' при завершении задачи (обязательное, загружает
